# ESB Meter Data

**Code version: `0.1.0-beta.8`** · [Version manifest](custom_components/esb_meter/manifest.json) · [Changelog](CHANGELOG.md) · [GitHub releases](https://github.com/narayanvs/ha-esb-meter/releases)

A Home Assistant custom integration for automatically downloading Irish ESB Networks smart-meter history. Works independently of your electricity supplier and live power monitoring. **Solar panels, batteries, inverters and Sigenergy are not required.** An ESB Networks account with access to downloadable smart-meter interval readings is required.

**Development beta:** real-account login, automatic initial download, entity setup and recorder history import have been verified on one HA installation through beta.7. The subsequent scheduled refresh and optional comparison feature still need live verification. Available through a HACS custom repository; not in the default HACS catalogue.

## Installation

Once the code is pushed to GitHub:

1. Open **HACS → ⋮ → Custom repositories**.
2. Add `https://github.com/narayanvs/ha-esb-meter`, category **Integration**.
3. Find **ESB Meter Data** in HACS and download it. HACS can install the default branch before a tagged release exists.
4. Restart Home Assistant.
5. Open **Settings → Devices & services → Add integration → ESB Meter Data**.
6. Enter your ESB Networks account email, password and 11-digit MPRN. The password field is masked. Choose whether to publish historical statistics.
7. Submit and allow the initial account login and history import to complete. Entities are created after a successful first retrieval.

HACS installs and updates the integration files; account setup happens in Home Assistant, not HACS. Requires Home Assistant 2026.10 or newer. No additional container, MQTT broker or manual CSV uploads are required.

## What it provides

- Separate import and export history with original timestamps for HA Energy statistics.
- Energy summaries for the latest complete day, observed current month and retained history; the complete-day date appears in attributes.
- Latest reading, data age, last successful download, next download, connection status, missing intervals, partial hours and corrections diagnostics.
- A refresh button and configurable download interval (24–168 hours).

ESB data is delayed: use your inverter or live meter for current power. These summaries are not “today so far” live measurements. Missing export data stays unavailable rather than becoming zero. Monthly totals include received intervals only and can be incomplete. Historical statistics can be selected in HA Energy once published; summary entities deliberately do not accumulate backfills as current-day energy.

## Entity reference

Entity IDs are generated by HA and can differ if renamed or if multiple meters are configured. Names below are relative to the **ESB Meter Data** device. Numeric energy values use **kWh**.

| Entity name | Meaning |
| --- | --- |
| Import / Export retained history | Total across the locally retained interval ledger, up to 730 days. Not necessarily a lifetime meter reading. |
| Import / Export latest complete day | Most recent complete Irish calendar day's energy; `latest_complete_day` identifies the date. |
| Import / Export month to latest reading | Received energy for the current Irish calendar month. Partial coverage is possible; unavailable if there are no current-month readings. |
| Latest interval end | End timestamp of the newest received half-hour interval. |
| Last successful download | Timestamp recorded when a retrieval/import attempt is successfully accepted. Replaying a saved pending download can also update this timestamp. |
| Next download | Earliest scheduled next retrieval time; the hourly scheduler may run it later. |
| Data lag | Hours since the newest received interval ended. ESB data is delayed. |
| Connection status | `ok`, a retrieval/setup phase or a safe error code. `ok` does not mean the source data is live. |
| Missing intervals | Import and export missing half-hours summed across their respective received history ranges. Missing data is not filled with zero. |
| Partial hours | Import/export hourly buckets containing fewer than two half-hour readings. Includes partially received boundary hours. |
| Corrected intervals | Changed overlapping intervals in the most recently accepted retrieval. Not an all-time counter. |
| Refresh meter data (button) | Request refresh; respects failure cooldowns. A successful daily download can be advanced once at least one hour has passed. |

With historical publication enabled, recorder also receives **ESB Import** and **ESB Export** external statistics. These are historical series for HA Energy, separate from the summary sensor entities. Do not add them alongside another source measuring the same grid energy in the same Energy dashboard configuration, or you may double-count.

Optional comparison entities are created for each direction:

| Entity name | Meaning |
| --- | --- |
| Import / Export comparison status | `not_configured`, `waiting_for_startup`, `incomplete_esb`, `incomplete_reference`, `reference_error`, `matched` or `anomaly`. |
| Import / Export comparison difference | Reference minus ESB in kWh, for the compared date. Unavailable without a valid comparison. |
| Import / Export comparison difference percent | Signed difference as a percentage of ESB energy; unavailable when ESB energy is zero. |

Comparison attributes identify the date, selected reference entity, both totals and thresholds. No comparison alert is sent automatically. The six optional comparison entities have no effect on the core import/export statistics.

## Downloads and storage

Downloads run daily by default, with a small scheduling offset. Existing sessions are reused. Login attempts are spaced by at least one minute and limited to three in a rolling 15-minute window, shared across integration entries and persisted across restarts. The old daily limit is automatically replaced when this version loads. Ordinary retrieval failures retry after 15 minutes; rejected credentials and HTTP rate limits back off for one hour, and browser-verification challenges for six hours. These are local safeguards, not published ESB limits. Manual refresh cannot bypass failure cooldowns.

CSV responses are parsed in memory and discarded. One normalized interval ledger per meter retains up to 730 days, plus small session/cadence metadata. Overlapping downloads update existing intervals; corrections replay affected hourly statistics. Corrections older than the retained window cannot be reconstructed. HA recorder retains its own long-term statistics according to HA behaviour; this integration does not delete those historical statistics when its local ledger rolls forward.

CSV kW values are converted to half-hour energy; calculated kWh files are accepted directly. Irish local interval-end timestamps are converted to UTC interval starts. DST repeated hours are resolved separately per channel; ambiguous or conflicting files are rejected instead of guessed. Missing intervals remain gaps; partial hours are reported.

## Privacy and reliability

Credentials are stored in HA config entries and session cookies in HA storage, never in the repository or integration diagnostics. HA storage and backups must be treated as private; this integration does not add encryption to HA storage. Diagnostics omit meter identifiers, credentials, cookies and raw readings.

This uses undocumented ESB portal endpoints, not a supported public API. Portal changes, CAPTCHA or account restrictions can prevent retrieval. CAPTCHA is not bypassed and unattended login cannot be guaranteed. Cached readings remain available during ordinary retrieval failures; rejected credentials request reauthentication.

## Optional comparison with another grid meter

**Disabled by default.** The core ESB integration works fully without reference sensors. Comparison entities display `not_configured` until a source is selected; no comparison recorder queries run when both sources are blank. There is no Sigenergy dependency or automatic assumption that a household has solar.

In the integration's **Configure** options, optionally select cumulative **grid import** and **grid export** energy sensors that have HA recorder statistics. Leave these blank if you do not have another meter. This feature is supplier/inverter independent; it does not compare household consumption or solar generation against grid energy.

Six comparison entities provide status, signed kWh difference and signed percentage for import and export. Attributes include the compared date, both totals and thresholds. Positive means the reference measured more than ESB. By default an anomaly requires a difference greater than **both 0.5 kWh and 5%**. Thresholds are adjustable; this is a diagnostic flag, not a billing fault conclusion. No phone notifications are enabled automatically.

Each direction uses its latest complete ESB Irish calendar day and requires all matching reference hourly change records (23/24/25 hours at DST). Recorder converts units to kWh, including MWh sources. Missing or negative reference changes are marked incomplete rather than compared. Hourly presence cannot detect every source outage within an otherwise recorded hour. Comparison updates locally with the hourly refresh without additional ESB requests.

## Restart behaviour

HA restores cached normalized readings, cookies, download/retry cadence and any pending import. A normal restart before the next download is due does not log in or download again. Restarting after a due time performs one retrieval using the cached session, signing in only if necessary. Stored cooldowns survive restarts. Overlapping downloads merge without duplicate energy. History already in recorder remains there.

Comparison queries wait until HA has started and never block startup on recorder completion. Pending imports are queued in bounded chunks; cached measurements remain available when the portal is temporarily unreachable. The stored next-download time can be serviced by the next hourly scheduler tick rather than at the exact displayed second.

## Publishing a release (maintainers)

Pushing ordinary code does not publish a release. To release a version, update `manifest.json`, add its `CHANGELOG.md` section, commit, then push a matching `v` tag **on a commit containing the release workflow**:

```sh
git push origin main
git tag v0.1.0-beta.8
git push origin v0.1.0-beta.8
```

Use the new manifest version for subsequent releases. Do not reuse or force-move published tags. If this example tag already exists, publish a new version instead.

The **Release** GitHub Action validates tag/version agreement and non-empty changelog notes, then runs the unit tests, hassfest and HACS checks before publishing. `alpha`, `beta` and `rc` tags are marked as pre-releases; a stable SemVer tag produces a regular release. Notes come from the matching changelog section. Existing releases are left unchanged if the workflow is rerun. It uses the repository's automatic `GITHUB_TOKEN`, with write permission limited to the publishing job; no personal access token or ESB credentials are needed.

Watch **Actions → Release** for progress. After success, the release appears on GitHub's **Releases** page. Pre-releases may require enabling beta versions in HACS to appear in its version selector. This does not submit the repository to the default HACS catalogue.
